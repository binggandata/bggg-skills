# App 解析：从 UI 语义树到规格（B 层净室版）

## 1. 解析输入

1. `uiautomator dump` XML：节点 `class`、`text`、`content-desc`、`resource-id`、`bounds`、`clickable`、`enabled`、`checked`、`scrollable`
2. 截图：颜色、字号（按 px 估）、圆角、间距、图片内容、动画中间态
3. 行为日志：`logcat`（崩溃/网络/播放错误）、`dumpsys`（当前 Activity）

## 2. 建立"元素图"

每一步先解析出**可点击元素列表**（`scripts/ui.py show`），再决定点哪个：
- 文本/描述 → 语义准确但可能为空（Compose 常见）
- 空 desc 的卡片：结合截图位置、父容器、相邻标题推断
- 列表/网格：记录 `bounds` 与列数、间距、卡片比例

## 3. 提取设计 Token

| Token | 提取方式 |
|---|---|
| 背景色/面板色/文字色 | 截图取色（注意深色主题 + 半透明叠加） |
| 强调色 | 按钮/选中态取色 |
| 字号/行高 | 由 bounds 高度与文字行数估算，再按 density 换算 dp |
| 圆角/间距 | 截图裁切测量 → px → /density |
| 控件高度 | 按钮/输入框 bounds 高度 → dp |
| 图标 | 记录形状/位置；用系统 Material Icons 近似，不复制原素材 |

## 4. 不同框架的解析难度

| 框架 | 语义树 | 备注 |
|---|---|---|
| 原生 Compose | 中（常缺 text/desc） | 需要截图+bounds 辅助 |
| 原生 View | 好（text/id/desc 全） | 首选直接遍历 |
| Flutter | 差（大量无语义节点） | 截图为主，必要时开启无障碍语义 |
| H5/WebView | 中 | 可结合页面源码/调试（在授权范围内） |
| 游戏/自绘 | 差 | 只能截图 + 固定坐标 + 图像识别 |

## 5. 动态状态采样

- 生成进度：每 3–5s dump 一次，记录百分比/文案/按钮变化
- 动画：多点截图；不要用单帧推断完整动效
- 列表滚动：记录首屏/滚动后/到底部的元素集合
- 失败/重试：断网/停止服务/取消操作触发，记录 Toast/Dialog/卡片状态

## 6. 输出规格（交给重建层）

- 页面清单（名称/入口/层级/URL-ish 标识）
- 导航图（触发元素 → 目标页 → 返回方式）
- 每页元素表（名称/类型/文案/位置/状态/交互）
- Token 表（色/字号/间距/圆角/高度）
- 状态矩阵（正常/空/加载/失败/选中/多版本/键盘/弹窗）
- 行为规格（提交/轮询/完成/失败/取消/通知/计费）
