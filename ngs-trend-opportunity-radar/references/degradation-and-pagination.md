# 数据降级与翻页

## 统一状态

每个数据源或请求批次使用以下状态之一：

- `success`：计划样本与字段完整，可按对应门槛使用。
- `partial`：拿到部分可用数据，但覆盖、字段或请求不完整。
- `blocked`：登录墙、验证码、403、challenge、限流或网络阻断，没有可用响应。
- `empty`：请求成功且语义正确，但结果为空；不能在未复核查询词和窗口前写成零需求。
- `semantic_mismatch`：返回结果与候选商品／场景不符；保留原始响应但不进入评级。
- `not_run`：未执行。

缺失与失败统一进入 `missing_evidence`。不得用零值、搜索摘要或相邻市场数字填补。

同一路线的瞬时网络、429 或 5xx 最多重试 1 次。登录墙、验证码、challenge、稳定 403 或明确限流立即停止该路线并记录；需要用户登录、验证码或新授权时向用户说明具体页面与动作。

Reddit 的降级不是放弃数据：结构化 OAuth／公共 JSON API失败后，切到用户已登录的 `old.reddit.com`；同源 `.json` 被拦截后再采明确标记的可见 DOM。

## Sorftime 商品翻页

1. `page=1` 返回后先本地语义检查、字段完整性检查和 ASIN 去重。
2. 累计获得 3～10 个相关代表 ASIN 时停止。
3. 不足 3 个时自动请求下一页，默认最多 3 页，包含第一页。
4. 每页保存原始响应和调用日志，记录返回数、语义相关数、字段完整数、去重后新增有效数。
5. 第 3 页仍不足时停止，向用户报告：已用页数、累计有效数、每页新增数和最后一页边际收益。
6. 继续前同时询问“是否继续翻页”以及“是否修改最大翻页上限”；未确认不进入第 4 页。

翻页只由代表商品不足触发，不因为想扩大样本而默认翻满。报告披露实际页数、总返回数、有效商品数、每页新增有效数和停止原因。
