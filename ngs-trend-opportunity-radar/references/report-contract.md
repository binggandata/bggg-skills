# 本地报告契约

HTML 的固定章节、图表、卡片、视觉与文案规范见 [`report-template.md`](report-template.md)。生成器不得绕过模板另造一套报告结构。

## 默认交付

在启动卡确认的 `output_location` 下创建本次运行目录，同一数据快照生成：

- `report/report.md`
- `report/report.html`
- `report/research_data.xlsx`：唯一面向用户的数据文件，内含多个渠道工作表
- `work/workbook-sources/*.csv`：仅供工作簿构建和机器校验，不作为报告下载项
- `analysis/opportunity_pool.json`
- `analysis/evidence_index.json`
- `analysis/amazon_pain_stats.json`
- `quality/validation.json`

新运行默认不写入 Skill 自身目录。Skill 根目录下的 `outputs/` 只可作为开发样例，不属于正式安装包，也不得被下一次运行当作数据源。

### 一次一品类

- 一个运行目录、一个 `research_brief.json` 和一套正式三件套只能对应一个研究品类。
- 用户一次提出多个品类时，按品类创建独立运行目录，分别采集、统计、渲染和校验。
- 不同品类不得共用候选池、样本计数、证据索引、Sorftime 调用数或工作簿。
- 跨品类总览只能作为所有单品类成果之外的可选附加件，不能替代任一品类的 HTML、Excel 或 Markdown。

### 用户正式收到

- HTML 主报告：决策阅读入口。
- 一个多工作表 Excel：全部渠道数据入口。
- Markdown：轻量文字版和后续飞书发布源。

同一个运行在两个决策节点都可以交付这三件套：

- **快筛阶段**：全部方向已经统一快筛，等待用户选择 Top N。HTML 展示候选对比和去留理由；Excel 的深验渠道表写明 `not_run` 与阶段原因。
- **深验阶段**：用户已选择 Top N，并完成 Sorftime 商品池与 Amazon 评论验证。HTML 增加代表 ASIN、买后痛点和产品改良方向。

两种阶段不得混写。快筛阶段没有 Amazon 评论是工作流尚未到达，不得写成平台失败；深验阶段若采集失败，则按实际状态披露。

渲染前必须显式传入本次运行的研究品类；若该品类不在候选数据中、筛选后为空，或输出仍包含另一研究品类，生成器应失败而不是输出混合报告。

内部 CSV、JSON／JSONL、截图和失败日志保留在运行目录用于追溯，不在报告中制造一排下载入口。

## 报告结构

1. **先讲研究范围**：目标市场、计划销售平台、用户给定的研究品类、Sorftime 返回数、语义有效方向数、三个免费源实际覆盖数、用户选择的 Top N；不能直接从某个具体产品开场。
2. **再给结论**：做不做、为什么、下一步做什么，控制在一屏。
3. **一句话数据覆盖**：用人话说清各渠道拿到多少；Reddit 同时披露父帖数、评论数和 `collection_mode`，不在正文堆失败日志；技术细节放折叠区。
4. **全候选漏斗**：每个有效方向都显示 Sorftime 类目规模，以及 Google Trends、TikTok、Reddit 的状态与关键数字，并给出“进入深验／观察／淘汰”、卡点和原因。TikTok 至少展示视频数、账号数、中位播放、最高播放和头部视频播放占比；`blocked`、字段缺失与真实弱信号分开。
5. **Top N 商品与买后验证**：对用户选择的每个方向展示 Sorftime 代表 ASIN 和 Amazon 买后问题。代表 ASIN 不能只显示编号，需同时展示商品图、标题、价格、评分、月销量和评论数。
6. **真实痛点**：Amazon 买后缺陷为主，TikTok 评论和达到独立父帖门槛的 Reddit 讨论为辅。Top N 大于 1 时，每个方向分别给出评论覆盖、前三痛点和反证，再保留一张合并痛点图作为总览。
7. **产品机会卡**：每个深验方向给出目标人群、场景、结构方向、最大反证、验证动作。
8. **风险与缺口**：只保留会改变决策的 3～5 项。
9. **证据和数据下载**：原文证据、source_id、URL，以及唯一的多工作表 Excel 下载入口。
10. **继续咨询**：报告末尾列出 3～5 个自然语言追问方向，包括扩大 Top N。

## 轻量可视化

报告内置 4～5 张 SVG 图表，不运行时调用 `bggg-voc-report`：

1. Google Trends 多词趋势折线；
2. TikTok 相关视频表现；
3. Sorftime 代表 ASIN 销量／评论门槛；
4. Amazon 低星痛点排序；
5. 候选机会对比（有多个候选时）。

每张图只回答一个业务问题，标题直接写结论，图下注明来源文件、n 和口径。异质指标不相加，不把视频播放量、搜索指数和销量放在同一分值里。

## 数字与引用

- 所有统计先由确定性脚本落盘，再进入 Markdown／HTML；图表数字只读落盘统计。
- 市场、语言、研究品类、Sorftime 返回方向数、有效候选数、用户选择的 Top N、趋势变化、样本量、ASIN 数和建议文案都从本次任务卡与落盘分析读取；不得复用示例运行中的国家、日期、商品词或指标。
- 每个关键结论至少挂一个原文证据；A 级关键结论优先挂两个独立父级证据簇。
- TikTok 视频和评论分别统计。
- 展示样本量、时间窗口、停止原因、平台／父级集中度和 Sorftime 调用总数。
- HTML 自包含，不依赖远程 CSS／JS；外链仅用于原始证据跳转。
- SVG 图表标签必须完整显示，不能因靠近右边界而裁掉评论数等关键信息。
- 证据卡可以先显示摘要，但必须提供报告内展开的完整原文；不能只保留截断文本。原始链接是补充，不替代完整落盘原文。

## 研究数据工作簿

`report/research_data.xlsx` 固定包含 10 个工作表：数据覆盖、Google Trends、TikTok 视频、TikTok 评论、Reddit 帖子、Reddit 评论、Sorftime 品类、Sorftime 商品、Amazon 评论、证据索引。每表冻结表头、启用筛选、合理设置列宽；Reddit 表额外保留父帖 ID 与 `collection_mode`。每行尽量保留 `source_id`、来源 URL、采集时间、目标／实际市场和原始文件。CSV 可以作为内部中间文件，但 HTML／Markdown 不得给出单独的 CSV 下载入口。

快筛阶段仍保留同样的 10 个工作表，方便后续在同一结构中补数据。尚未运行的工作表至少有一行 `status=not_run` 和人话原因，不能是完全空白页。

## 飞书

本地报告完成不等于已发布。只有用户确认本地报告、目标文档位置、机器人通知群和发送内容后，才进入 `feishu-publishing.md`。
