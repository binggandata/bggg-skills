# 趋势选品启动卡

首次调用先确认业务目标和交付位置，再开始数据采集。对用户展示 3 项业务信息和 1 项交付设置；用户可以填写卡片，也可以用自然语言回答，Agent 自动整理，不要求重复已经提供的信息。

## 用户填写版

```text
【趋势选品启动卡】

1. 研究品类：
2. 目标市场：
3. 平台：
4. 输出位置：
```

最短回复示例：

> 家居收纳｜美国｜Amazon｜桌面/趋势选品报告

Sorftime 连接状态不是启动卡字段。首次使用时若当前环境尚未连接 Sorftime，先给出配置入口 `https://open.sorftime.com/mcp`，告诉用户注册后按页面说明配置 MCP；可以说明“首次注册赠送 3 天、100 次调用”，并注明活动以页面最新规则为准。Key 只填写在当前 AI 工具的 MCP 设置中，配置后用户只回复“已配置”。不要要求用户把 Key 粘贴到对话中，不读取、不回显、不落盘，也不把 Key 写进 Skill 或报告。

## 必填字段

- `requested_market`：目标国家或地区；可以是 Sorftime 未覆盖的市场。
- `target_sales_platform`：用户最终准备销售的平台。它不等于研究数据源；若用 Amazon 数据辅助判断 TikTok Shop 或独立站机会，必须明确写成参考信号。
- `broad_category`：用户确认的研究品类，例如家居收纳、宠物清洁或户外照明。它不要求是平台一级类目，但应能容纳多个互相独立、可搜索、可对应具体商品集合的方向。不能从某个具体子产品反推并替用户默选。
- `output_location`：用户指定的本地输出目录，可以是绝对路径或清楚的自然语言位置。若用户回答“默认”，解析为当前工作目录下的 `trend-radar-outputs/<date>_<market>_<category>/`。默认不得把新运行产物写进 Skill 根目录。

缺少上述任一项时，只追问缺失项。用户已经在自然语言中说明的内容直接预填，不再让用户重新填写整张卡。输出位置是交付设置，不参与候选评分。不得把下方内部默认字段继续展示给用户填写。

## Agent 内部默认字段

- `research_goal`：默认“从研究品类中筛选值得继续验证的产品方向”。
- `allowed_categories`／`excluded_categories`：默认无额外限制，但遵守用户明确排除项。
- `target_price`／`minimum_margin`／尺寸重量／合规限制：默认未知，不因缺失阻止趋势快筛；进入打样建议时标为待确认。
- `days_to_market`：默认未知；不自动倒推出上架日期。
- `known_clues`：关键词、竞品、ASIN 或社交内容线索；用户给出的明确产品线索优先用于查询和核对。
- `selection_scope`：固定为 `all_directions_screen_then_user_top_n`。候选发现后覆盖全部有效方向；免费快筛完成前 `selected_top_n=null`，不得替用户默选。
- 输出默认本地中文 Markdown、HTML 和多工作表 Excel；飞书发布不放在首次业务卡中，报告确认后另行授权。

## Agent 补齐的执行字段

- `workflow_version`：固定写 `all-directions-funnel-v2`。
- `seed_terms`：Sorftime 候选发现返回并通过语义筛选的全部有效商品方向，同时保存本地语言名称、搜索词、Node ID、市场规模和纳入理由；不得只截取销量最高的固定数量。
- `excluded_directions`：未进入快筛的原始子类目、状态和明确排除原因。
- `free_source_statuses`：每个候选的 Google Trends、TikTok、Reddit 状态。
- `selected_top_n`：免费快筛完成后由用户明确选择的深验数量；选择前保持 `null`。
- `deep_validation_candidate_ids`：用户确认进入深验的候选 ID 列表。
- `observed_market`：每个数据源实际反映的市场；不能因为查询参数写了某国就假装内容一定来自该国。
- 查询语言与当地常用说法。
- 数据源、查询式、时间窗口、样本上限和停止条件。
- Sorftime 计划工具、预计调用次数、软／硬上限。
- 本地输出目录、不支持项和降级方案。

## 术语与粒度

- **研究品类**：用户的业务范围，例如“家居收纳”“宠物清洁”。启动卡统一使用这个说法。
- **子类目**：Sorftime／Amazon 分类树返回的正式类目节点，必须带来源名称和 Node ID。
- **候选方向**：将语义相关的子类目去重、统一粒度后形成的跨平台研究对象，例如“抽屉分隔板”“猫砂垫”。Google Trends、TikTok 和 Reddit 都按候选方向及当地搜索词统一调研。
- **Top N**：全部候选方向完成三源快筛后形成的优先级；不是 Sorftime 第一次返回时就选出的销量 Top。

模型不得在 Sorftime 候选发现之前凭经验生成固定数量的候选方向。模型只负责把 Sorftime 返回的子类目做语义筛选、去重和跨平台查询词转换。

### 粒度判断

启动卡中的“研究品类”是研究入口，不等于最终产品，也不要求用户知道 Amazon 的正式类目树。

| 粒度 | 示例 | 处理方式 |
|---|---|---|
| 太宽 | Home & Kitchen、Pet Supplies | 先让用户收窄到一个消费任务或使用场景 |
| 合适 | 家居收纳、宠物清洁 | 进入 Sorftime 候选发现，再调研全部有效候选方向 |
| 候选方向 | 抽屉分隔板、猫砂垫、宠物洗爪杯 | 作为独立商品市场进入免费快筛 |
| 太细 | 竹制可伸缩抽屉分隔板 4 件套 | 跳过候选发现，改走单品／产品方案验证 |

判断标准：研究品类下面应能形成多个消费者会单独搜索、Amazon 上有独立商品集合、Sorftime 可映射类目或商品市场的方向。Sorftime 返回项用于建立候选全集；重复、品牌词、抽象需求、非商品节点和语义偏题项必须进入 `excluded_directions`，不能为了凑数保留。

## 确认闸门

1. 收到用户回复后，先按“研究品类 → 目标市场 → 平台 → 输出位置”回显启动卡，并把相对路径解析成明确的本地目录。
2. 检查 Sorftime MCP 是否已连接。已连接则只回显“已连接”；未连接则给出 `https://open.sorftime.com/mcp`、注册权益和活动口径，提示用户在 MCP 设置中填写自己的 Key，并等待其回复“已配置”，不要接收或保存明文 Key。
3. 只读检查可用登录环境；检测到多个时按 [`login-session-routing.md`](login-session-routing.md) 让用户先选择。该问题只在需要时出现，不加入固定业务卡。
4. 显示 Sorftime 候选发现计划、各渠道逐方向样本范围、候选发现调用次数、登录态选择和市场覆盖风险。此时还没有候选方向，不得先用模型猜一份名单。
5. 用户明确说“开始”“按这个跑”或同义表达后，先运行 Sorftime 候选发现。
6. 展示 Sorftime 原始子类目、语义有效候选方向与 `excluded_directions`；用户确认候选范围后，才运行 Google Trends、TikTok 和 Reddit。
7. 免费快筛完成后展示所有方向的证据与排名，再让用户明确选择 Top N。选择前不调用 `product_search`。
